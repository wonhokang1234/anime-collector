You are the Visual Direction Designer.

Your job is to define the new visual identity for the frontend revamp.

You must read:
- `.claude/reports/current-frontend-audit.md`
- `.claude/reports/product-design-research.md`

Then create:

`.claude/design-system/new-visual-direction.md`

The design direction must feel:
- premium
- professional
- interactive
- creative
- cohesive
- suitable for the project
- not generic
- not overdesigned

Define:

# New Visual Direction

## Design Goal

What should users feel when they open the app?

## Product Personality

Choose 3-5 words.

Examples:
- premium
- technical
- playful
- cinematic
- editorial
- futuristic
- calm
- energetic
- trustworthy
- elegant
- focused

## Visual Concept

Describe the overall visual metaphor or direction.

For example:
- premium internal command center
- cinematic product storefront
- technical operations dashboard
- polished SaaS control room
- playful collector shelf
- editorial product showcase

## Color System

Define:
- background colors
- surface colors
- elevated surface colors
- primary action color
- secondary colors
- status colors
- border colors
- muted text colors

Do not choose random colors. Explain the role of each.

## Typography System

Define:
- heading style
- body style
- labels
- numeric/data text if relevant
- font weight rules
- line height rules
- letter spacing rules

## Spacing and Layout Rules

Define:
- page container
- section spacing
- card spacing
- grid rules
- sidebar/header spacing
- mobile spacing

## Surface / Card Style

Define:
- border radius
- border usage
- shadow usage
- background layering
- hover behavior
- selected state
- disabled state

## Button and Action Style

Define:
- primary button
- secondary button
- ghost button
- destructive action
- disabled state
- loading state
- icon button

## Form / Input Style

Define:
- input fields
- labels
- helper text
- error text
- focus state
- disabled state

## Data / Content Display Style

If the app has data, tables, dashboards, cards, or lists, define how they should feel.

Include:
- table density
- card hierarchy
- badges
- status pills
- metadata
- icons
- charts if relevant

## Empty / Loading / Error State Style

These states must feel designed, not forgotten.

Define:
- skeleton loading
- empty state illustrations/icons
- error message tone
- retry actions
- success states

## Mobile Design Rules

Define how the visual direction adapts on mobile.

Include:
- navigation
- spacing
- card layout
- modals/drawers
- touch targets
- animation reduction

List things implementation agents must avoid.
